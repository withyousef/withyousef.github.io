عشرة تمارين — أول if وif/else

إعداد: يوسف زكريا التهامى · تأسيس البرمجة · بكالوريا ٢٠٢٧

القاعدة الوحيدة

جاوب الأول، وبعدين اكشف. لو كشفت قبل ما تفكّر، التمرين بيبقى ملوش أى لازمة — إنت بتخدع نفسك مش المدرس.

و«الصندوق» هنا هو نفسه «الدرج» بتاع المحاضرة، وهو نفسه اللى الكتب بتسمّيه متغير.

القسم الأول · ٨ أسئلة

اختار

٠١

طلب شحن — الشرط طلع غلط، فإيه اللى بيحصل بعده؟

اختيار من متعدد

الكتلة فيها سطرين. لو الشرط طلع false، اللى بعد الكتلة بيشتغل ولا البرنامج بيقف؟

let stock = 3;
let sold = 5;

console.log(stock >= sold);

if (stock >= sold) {
  console.log("Order shipped");
  stock = stock - sold;
}

console.log("Order closed");
console.log(stock);

الإجابة الصح هى أ

الناتجfalse Order closed 3

السطر الرابع بيطبع ناتج المقارنة نفسه: 3 >= 5 يعنى false. وده مش شرطاً — ده مجرد قيمة بتتطبع زى أى قيمة تانية.

وبعدين ييجى if بنفس المقارنة. وطالما طلعت false، الكمبيوتر بيقفز فوق القوسين المعقوفين كلهم — السطرين اللى جواهم ما اشتغلوش، لا الطباعة ولا الطرح.

وعشان كده stock فضل ٣. لو الطرح كان اشتغل كان بقى -2، والاختيار ده موجود قدامك عشان لو اخترته تعرف إن ده اللى إنت فاكره.

والنقطة الأهم: البرنامج ما وقفش. السطران اللى بعد القوس المعقوف الأخير بره الكتلة، فبيشتغلوا عادى مهما كان الشرط.

الخلاصة: if بتتحكم فى اللى جوّه قوسيها بس. ولا سطر بره الكتلة بيتأثر بها.

الشرح خطوة بخطوة
٠١

المقارنة قيمة، مش شرط

console.log(stock >= sold);   // false

قبل ما نستعملها فى if، خلّينا نشوفها لوحدها. دى قيمة كاملة زى الرقم والنص.

٠٢

الشرط false، فالكتلة كلها اتخطّت

if (stock >= sold) {
  console.log("Order shipped");
  stock = stock - sold;
}

مش الطباعة بس هى اللى اتخطّت — كل سطر بين القوسين المعقوفين اتخطّى.

٠٣

واللى بره الكتلة اشتغل عادى

console.log("Order closed");
console.log(stock);   // 3

القوس المعقوف اللى بيقفل هو حدّ سلطة if. بعده البرنامج بيرجع يمشى عادى.

٠٢

قراءة حرارة — تلات شروط ورا بعض

اختيار من متعدد

تلات if منفصلين، وكل واحد بقوسيه. كام واحد فيهم بيتحسب؟

let temp = 34;

if (temp > 30) {
  console.log("Hot");
}

if (temp > 40) {
  console.log("Very hot");
}

if (temp > 20) {
  console.log("Warm");
}

console.log("Reading done");

الإجابة الصح هى ج

الناتجHot Warm Reading done

التلات if دول مالهمش علاقة ببعض خالص. كل واحد فيهم جملة مستقلة، والكمبيوتر بيمرّ عليهم واحداً واحداً ويحسب كل شرط لوحده.

34 > 30 صح فطبع Hot. و34 > 40 غلط فاتخطّى. و34 > 20 صح فطبع Warm.

أشهر غلط هنا إن الطالب يفتكر إن أول شرط يتحقق بيقفل اللى بعده. ده مش صحيح مع if منفصلة — ده بيحصل بس مع else واللى هيجى بعده، وإحنا لسه ما وصلناش.

جرّب تعدّها كده: كام if فى الكود؟ تلاتة. يبقى كام شرط اتحسب؟ تلاتة. الشروط بتتحسب كلها، واللى بيختلف هو الكتل اللى اشتغلت.

القاعدة: كل if بقوسيها المستقلين = سؤال مستقل، والإجابة عليه ما بتمنعش السؤال اللى بعده.

الشرح خطوة بخطوة
٠١

تلات أسئلة مستقلة، مش سلسلة

if (temp > 30) { ... }
if (temp > 40) { ... }
if (temp > 20) { ... }

شوف العمود الأوسط: التلات نواتج موجودين. مفيش شرط اتلغى.

٠٢

التانى وحده هو اللى وقع

if (temp > 40) {
  console.log("Very hot");
}

أربعة وتلاتين مش أكبر من أربعين، فالسطر ده وحده هو اللى ما اشتغلش.

٠٣

والتالت اشتغل رغم إن الأول اشتغل قبله

if (temp > 20) {
  console.log("Warm");
}

ده بيت القصيد: Hot اللى اتطبعت فوق ما منعتش Warm من إنها تتطبع.

٠٣

محفظة — فرع واحد بس بيشتغل

اختيار من متعدد

خد بالك من سطر الطرح: هو جوّه أنهى فرع، والفرع ده اشتغل ولا لأ؟

let balance = 120;
let price = 150;

if (balance >= price) {
  balance = balance - price;
  console.log("Paid");
} else {
  console.log("Not enough");
}

console.log(balance);

الإجابة الصح هى د

الناتجNot enough 120

120 >= 150 طلعت false، فالكمبيوتر مشى فى فرع else وطبع Not enough.

وفرع if اتخطّى بالكامل — بسطرَيه. يعنى balance = balance - price ما اشتغلش، والصندوق فضل بـ١٢٠.

كتير بيقعوا فى إن سطر الطرح ده «شغل داخلى» فبيشتغل على أى حال. لأ. السطر ده جوّه القوسين المعقوفين زيه زى الطباعة بالظبط، والاتنين مصيرهم واحد.

ومع if/else فيه ضمانة جديدة: واحد من الاتنين لازم يشتغل، وواحد بس. مستحيل يشتغلوا مع بعض، ومستحيل ما يشتغلش ولا واحد.

وآخر سطر بره الاتنين، فبيشتغل مهما كان الطريق اللى اتاخد. عشان كده 120 اتطبعت.

الشرح خطوة بخطوة
٠١

الشرط بيتحسب مرة واحدة، والطريق بيتحدّد

if (balance >= price) { ... } else { ... }

الطريق الباهت موجود فى الكود، بس الكمبيوتر ما مرّش عليه أصلاً.

٠٢

وسطر الطرح كان جوّه الطريق المتخطّى

balance = balance - price;   // ما اشتغلش

لو كان اشتغل كان الرصيد بقى -30، وده الاختيار اللى موجود قدامك.

٠٣

واللى بعد الكتلتين بيشتغل دايماً

console.log(balance);   // 120

أياً كان الفرع اللى اتاخد، البرنامج بيكمّل من هنا.

٠٤

تذكرة دخول — الشرط اتحسب مرة واحدة واتخزّن

اختيار من متعدد

الصندوق allowed اتحط فيه ناتج مقارنة. لاحظ إن age بيتغيّر فى آخر البرنامج.

let age = 15;
let allowed = age >= 18;

console.log(allowed);
console.log(typeof allowed);

if (allowed) {
  console.log("Enter");
} else {
  console.log("Wait");
}

age = 20;
console.log(allowed);

الإجابة الصح هى هـ

الناتجfalse boolean Wait false

السطر التانى فيه فكرتان مع بعض: المقارنة age >= 18 بتتحسب الأول فتطلع false، وبعدين القيمة دى بتتحط فى الصندوق. زى let x = 2 + 3 بالظبط — بيتخزّن ٥، مش «٢ + ٣».

وtypeof allowed بترجّع boolean — النوع التالت اللى شفناه فى المحاضرة اللى فاتت. مش string، لأن false هنا مش كلمة مكتوبة بين تنصيص.

if (allowed) شغّالة عادى، لأن اللى if محتاجاه هو true أو false — ومش مهم جه من مقارنة مكتوبة فى مكانها ولا من صندوق.

وآخر سطرين هما الفخ: غيّرنا age لـ٢٠، وطبعنا allowed تانى فطلعت false برضه. الصندوق خزّن الناتج ساعتها، مش المقارنة نفسها. مافيش خيط فاضل رابط بينهم.

ولو عايزها تتحدّث، لازم تكتب allowed = age >= 18; تانى بعد ما غيّرت العمر — عشان المقارنة تتحسب من جديد.

الشرح خطوة بخطوة
٠١

المقارنة بتتحسب الأول، والناتج بيتخزّن

let allowed = age >= 18;

نفس قاعدة التراكم اللى اتعلمناها: احسب اليمين الأول، وبعدين خزّن.

٠٢

والنوع اللى اتخزّن اسمه boolean

console.log(typeof allowed);   // boolean

لو كان "false" بين تنصيص كان النوع طلع string — وساعتها الحكاية بتختلف تماماً.

٠٣

وتغيير age بعد كده ما بيرجعش عليه

age = 20;
console.log(allowed);   // لسه false

الصندوق مش معادلة بتتحدّث لوحدها — هو مكان فيه قيمة اتحطّت مرة.

٠٥

نقاط اللاعب — الترتيب بيفرق

اختيار من متعدد

الشرط الأول بيغيّر points. الشرط اللى بعده بيشوف القيمة القديمة ولا الجديدة؟

let points = 90;

if (points >= 80) {
  points = points - 50;
  console.log("Bronze");
}

if (points >= 80) {
  console.log("Silver");
}

if (points >= 40) {
  console.log("Copper");
}

console.log(points);

الإجابة الصح هى و

الناتجBronze Copper 40

الشرط الأول: 90 >= 80 صح. فدخلنا الكتلة، طرحنا ٥٠ فبقى points يساوى ٤٠، وطبعنا Bronze.

الشرط التانى مكتوب بالحرف زى الأول: points >= 80. بس القيمة اتغيّرت، والكمبيوتر بيقرا الصندوق دلوقتى مش من شوية. 40 >= 80 غلط، فـSilver ما اتطبعتش.

الشرط التالت: 40 >= 40. علامة >= يعنى «أكبر أو يساوى»، والتساوى داخل. فطبع Copper.

والدرس اللى ورا التمرين ده: الشرط مش بيتحسب لما تكتبه، بيتحسب لما الكمبيوتر يوصل له. ولو حاجة اتغيّرت فى السطور اللى فوق، الشرط بيشوف الجديد.

وعشان كده لو نقلت ترتيب الشروط دى، الناتج هيتغيّر بالكامل — وده مش عيباً فى الكود، ده معناه إن الترتيب جزء من المنطق.

الشرح خطوة بخطوة
٠١

الكتلة الأولى غيّرت الصندوق

points = points - 50;   // 90 - 50

مافيش حاجة اسمها «تغيير مؤقت جوّه الكتلة». اللى اتغيّر اتغيّر.

٠٢

والشرط اللى بعده شاف القيمة الجديدة

if (points >= 80) {
  console.log("Silver");
}

الشرطان متطابقان حرفاً بحرف، وناتجهما مختلف. واللى اتغيّر هو الصندوق مش الشرط.

٠٣

وأربعين يساوى أربعين، فالتالت اشتغل

if (points >= 40) {
  console.log("Copper");
}

لو كانت > بس، كانت طلعت false وCopper ما كانتش اتطبعت.

٠٦

سعر جاى من المستخدم — علامتان بيتعاملوا معاه بشكلين

اختيار من متعدد

الصندوق price فيه نص. تابع كل مقارنة على حدة.

let price = "120";   // جاى من خانة كتب فيها المستخدم

console.log(price > 100);
console.log(price === 120);

if (price > 100) {
  console.log("Expensive");
}

if (price === 120) {
  console.log("Exact match");
} else {
  console.log("No match");
}

الإجابة الصح هى ب

الناتجtrue false Expensive No match

دى نفس حكاية المحاضرة اللى فاتت بالظبط، بس دلوقتى جوّه شرط. علامة > مالهاش غير معنى واحد — مقارنة أرقام. فلما لقت نصاً، حوّلته لرقم لوحدها: 120 > 100 يعنى true.

وعلامة === عكسها تماماً: بتقارن القيمة والنوع، وما بتحوّلش حاجة. و"120" نص و120 رقم، فالنوع مختلف والناتج false — حتى والرقم المكتوب واحد.

وعشان كده الـif الأولى دخلت وطبعت Expensive، والتانية ما دخلتش فراح الشغل لـelse وطبعت No match.

خد بالك إن السطرين الأولانيين بيطبعوا نواتج المقارنة نفسها. لو غطّيت الـif بإيدك وقريت السطرين دول بس، تبقى عرفت الإجابة كلها.

ودى مشكلة حقيقية بتحصل يومياً: أى حاجة بتيجى من المستخدم بتيجى نصاً، فالشرط === 120 بيفضل false للأبد والمبرمج مش فاهم ليه. والحل: Number(price) === 120.

الشرح خطوة بخطوة
٠١

علامة أكبر من بتحوّل لوحدها

console.log(price > 100);   // true

زى علامة الضرب والطرح بالظبط — واحدة المعنى، فبتحوّل.

٠٢

وعلامة يساوى الصارمة ما بتحوّلش

console.log(price === 120);   // false

لو كانت == كانت طلعت true وخبّت المشكلة. و=== بتفضحها.

٠٣

فالشرط التانى وقع، وelse اشتغلت

if (price === 120) { ... } else { ... }

else مش اختيارية لما الشرط يقع — دى الضمانة بتاعتها: واحد لازم يشتغل.

٠٧

وزن الشحنة — التحويل فشل، فالشرط عمل إيه؟

اختيار من متعدد

المستخدم كتب الوحدة مع الرقم. تابع الصندوق ونوعه، وبعدين قرّر الشرط راح فين.

let input = "30kg";
let weight = Number(input);

console.log(weight);
console.log(typeof weight);

if (weight > 20) {
  console.log("Heavy");
} else {
  console.log("Check the input");
}

console.log(weight + 5);

الإجابة الصح هى د

الناتجNaN number Check the input NaN

Number("30kg") بترجّع NaN. هى ما بتسحبش الأرقام من جوّه النص — إما النص كله رقم، وإلا NaN.

وtypeof NaN بترجّع number، وده غريب لأول وهلة. معنى الاسم نفسه «ليس رقماً»، بس هو قيمة بتعيش جوّه نوع الأرقام — زى ما نقول رقم بايظ.

وهنا الجديد: أى مقارنة فيها NaN بترجّع false. NaN > 20 غلط، وكمان NaN < 20 غلط. فالشرط وقع وراح لـelse.

وآخر سطر: NaN + 5 بتساوى NaN. القيمة البايظة بتنتشر فى كل حساب بعدها من غير ما البرنامج يقع.

والفايدة العملية: else هنا مش «الحالة التانية»، دى شبكة الأمان. لو المستخدم كتب حاجة غلط، البرنامج بيقول له بدل ما يكمّل بقيمة بايظة.

الشرح خطوة بخطوة
٠١

التحويل فشل، والناتج NaN

let weight = Number(input);   // NaN

حرفان زيادة بس، والنص كله بقى غير قابل للتحويل.

٠٢

ونوعه number رغم اسمه

console.log(typeof weight);   // number

يعنى typeof وحدها مش كفاية عشان تعرف إن القيمة سليمة.

٠٣

والمقارنة على NaN بتقع دايماً

if (weight > 20) { ... } else { ... }

ولو كتبت weight < 20 كانت هتقع برضه. وNaN مش أكبر ولا أصغر ولا يساوى.

٠٨

مراجعة — تراكم ونوع بيتقلب فى النص

اختيار من متعدد

مفيش شروط هنا خالص. تابع base وقيمته ونوعه بعد كل سطر.

let base = 10;
let bonus = "5";

base = base + 5;
console.log(base);
console.log(typeof base);

base = base + bonus;
console.log(base);
console.log(typeof base);

console.log(Number(base) + 1);

الإجابة الصح هى و

الناتج15 number 155 string 156

السطر التالت: 10 + 5. الاتنين أرقام، فالزائد جمع عادى والناتج 15 رقم.

والسطر السابع هو نقطة الانقلاب: 15 + "5". علامة الزائد شافت نصاً فى طرف، فقلبت من جمع للزق — والناتج "155" نص.

خد بالك إن القيمة بقت أكبر بكتير من اللى المفروض تطلع (٢٠)، والبرنامج ما وقعش بخطأ ولا حذّرك. ده اللى بيخلّى الغلط ده غدّاراً.

وآخر سطر: Number("155") بترجّع الرقم ١٥٥ — التحويل نجح لأن النص كله أرقام. وبعدين 155 + 1 جمع أرقام عادى فطلع 156.

والقاعدة اللى تفضل معاك: علامة الزائد وحدها هى اللى ليها معنيان. لو ما عرفتش نوع الطرفين، ما تعرفش هيجمع ولا هيلزّق.

الشرح خطوة بخطوة
٠١

رقم زائد رقم: جمع

base = base + 5;   // 15

لحد هنا كل حاجة طبيعية، والنوع number.

٠٢

ورقم زائد نص: لزق

base = base + bonus;   // "155"

الطريق الباهت هو اللى كنت متوقعه. والمتّبع هو اللى حصل فعلاً.

٠٣

والتحويل بيرجّعه رقماً تانى

console.log(Number(base) + 1);   // 156

التحويل نجح هنا لأن النص كله أرقام — مافيش حرف ولا مسافة.

٠٩

المشروع الأول — بوابة دخول القاعة

كتابة

اكتب برنامجاً كاملاً بالمواصفات دى، بالترتيب: ١ — صندوق name فيه "Omar"، وصندوق mark فيه الرقم ٦٨، وصندوق paid فيه النص "200". ٢ — اطبع نوع paid عشان تثبت إنه نص. ٣ — صندوق fee فيه paid محوّلاً لرقم بـNumber(). ٤ — if لوحدها (من غير else): لو fee أكبر من أو يساوى ٢٠٠، اطبع Fee ok. ٥ — if ومعاها else: لو mark أكبر من أو يساوى ٦٠ اطبع Pass، وغير كده اطبع Fail. ٦ — if تالتة مستقلة: لو mark أكبر من أو يساوى ٨٥، اطبع Top. ٧ — وفى الآخر، بره أى كتلة، اطبع سطراً بالشكل ده بالظبط: Omar 68

واكتب تحت البرنامج النواتج المتوقعة سطراً سطراً.

اتحفظت 
let name = "Omar";
let mark = 68;
let paid = "200";
console.log(typeof paid);
let fee = Number(paid);
if (fee >= 200) {
  console.log("Fee ok");
}
if (mark >= 60) {
  console.log("Pass");
} else {
  console.log("Fail");
}
if (mark >= 85) {
  console.log("Top");
}
console.log(name + " " + mark);
الناتجstring Fee ok Pass Omar 68

أربع نواتج بس، رغم إن فى البرنامج تلات شروط. عدّها معايا: Fee ok اتطبعت، وPass اتطبعت، وTop لأ — لأن ٦٨ مش أكبر من أو يساوى ٨٥.

الشرط الأول بيوضّح ليه التحويل مهم: fee رقم لأننا حوّلناه، فـfee >= 200 مقارنة أرقام نضيفة. ولو سبناه نصاً كانت المقارنة هتشتغل برضه (علامة >= بتحوّل لوحدها)، بس اللى بيقرا كودك مش هيعرف إنك واخد بالك.

والشرط التانى والتالت مالهمش علاقة ببعض. اللى بينهم إن الاتنين بيسألوا عن mark وبس. else بتاعة الشرط التانى تخص الشرط التانى لوحده، وما بتمنعش الشرط التالت من إنه يتحسب.

وده الفرق اللى لازم يترسّخ: if/else = طريقان لسؤال واحد. وif بعديها if = سؤالان منفصلان.

وآخر سطر بره الكل، فبيتطبع مهما كانت نتايج الشروط. المسافة فى " " مقصودة — من غيرها هيطلع Omar68.

ولو خلّصت بدرى: جرّب غيّر mark لـ٩٠ وشوف الناتج بقى إيه. المفروض تلات سطور بدل اتنين، لأن Top هتدخل.

الشرح خطوة بخطوة
٠١

حوّل قبل المقارنة

let fee = Number(paid);   // 200 رقم

اكتب Number() حتى لو المقارنة هتحوّل لوحدها — عشان اللى بيقرا كودك يفهم نيّتك.

٠٢

شرط بـelse: طريق واحد بالضبط

if (mark >= 60) {
  console.log("Pass");
} else {
  console.log("Fail");
}

مستحيل يطلعوا الاتنين، ومستحيل ما يطلعش ولا واحد. دى ضمانة else.

٠٣

وشرط تالت مستقل تماماً

if (mark >= 85) {
  console.log("Top");
}

الشرط ده بيتحسب على أى حال، حتى لو الشرط اللى قبله اتحقق.

١٠

المشروع التانى — صلّح البرنامج المكسور

كتابة

البرنامج ده المفروض يدّى شهادة للطالب اللى عدّى بس. وهو شغّال من غير ما يقع بخطأ، بس بيطبع الشهادة لطالب راسب: let mark = 45; if (mark >= 50) console.log("Pass"); console.log("Certificate"); if (mark < 50) { mark = mark + 5; console.log("Second chance"); } if (mark >= 50) { console.log("Pass after retry"); } console.log(mark);

لاحظ إن الشرط الأول مالوش قوسان معقوفان. المطلوب تلات حاجات:

١ — اكتب اللى بيطبعه دلوقتى بالظبط، سطراً سطراً. ٢ — اكتب البرنامج مصلّحاً بحيث: Pass وCertificate الاتنين ما يطبعوش غير لما mark يكون ٥٠ فأكتر، وبحيث الشرط الأول وmark < 50 يبقوا if/else واحداً بدل شرطين منفصلين. ٣ — قول فى سطر واحد ليه القوسان المعقوفان مش «زينة».

اتحفظت 
let mark = 45;
if (mark >= 50) {
  console.log("Pass");
  console.log("Certificate");
} else {
  mark = mark + 5;
  console.log("Second chance");
}
if (mark >= 50) {
  console.log("Pass after retry");
}
console.log(mark);
الناتج الحالىCertificate Second chance Pass after retry 50

الناتج الحالى أربعة سطور، وأولهم هو الكارثة: Certificate اتطبعت لطالب مجموعه ٤٥.

ليه: if من غير قوسين معقوفين بتاخد سطراً واحداً بس — السطر اللى بعدها مباشرةً. فـconsole.log("Pass") هى وحدها اللى تحت الشرط، وconsole.log("Certificate") جملة مستقلة تمام زى ما تكون مكتوبة فى آخر البرنامج.

والإزاحة خدعتك. المسافات دى للعين بس — الكمبيوتر ما بيقراش الإزاحة خالص، بيقرا القوسين. وعشان كده Pass ما اتطبعتش (٤٥ مش ٥٠ فأكتر) وCertificate اتطبعت.

وباقى الناتج: 45 < 50 صح، فـmark بقى ٥٠ واتطبعت Second chance. وبعدين الشرط التالت شاف القيمة الجديدة ٥٠، فطبع Pass after retry، وآخر سطر طبع 50.

التصحيح: حُطّ قوسين معقوفين حوالين السطرين، وحوّل الشرط التانى لـelse. والناتج بيبقى تلات سطور: Second chance وPass after retry و50 — والشهادة اختفت.

وليه else أحسن من if تانية: الشرطان mark >= 50 وmark < 50 عكس بعض، فكتابتهم منفصلين معناها إن الكمبيوتر بيحسب نفس السؤال مرتين — ولو غيّرت رقماً فى واحد ونسيت التانى، البرنامج بيبقى فيه حالة مالهاش إجابة. وelse بتلغى الاحتمال ده من أصله.

وسطرك الأخير ينفع يبقى: «القوسان المعقوفان هما اللى بيحدّدوا الكتلة، مش الإزاحة — ومن غيرهم if بتاخد سطراً واحداً بس.»

الناتج بعد التعديلSecond chance Pass after retry 50
الشرح خطوة بخطوة
٠١

من غير قوسين، الشرط بياخد سطراً واحداً

if (mark >= 50)
  console.log("Pass");      // ده تحت الشرط
  console.log("Certificate");   // وده مستقل خالص

غطّى الإزاحة بإيدك واقرا الكود تانى — هتلاقى السطر التانى جملة عادية زى أى جملة.

٠٢

والشرط اللى بعده غيّر القيمة

if (mark < 50) {
  mark = mark + 5;   // 45 + 5
}

وعشان كده الشرط التالت اشتغل — مش لأن الطالب عدّى من الأول، لأن الدرجة اتغيّرت فى النص.

٠٣

وبعد التصليح، طريق واحد بس

if (mark >= 50) {
  ...
} else {
  ...
}

القوسان ضمّوا السطرين مع بعض، وelse ضمنت إن واحداً من الطريقين بس هو اللى يمشى.
